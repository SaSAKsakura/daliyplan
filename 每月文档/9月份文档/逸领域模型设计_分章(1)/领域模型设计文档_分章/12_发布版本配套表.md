## 12. 发布版本配套表（prod_）

> **发布版本管理**（第 12 章，`prod_` 前缀）：支撑 1.6 节的发布/版本管理机制——
> 记录配置在研发固化域内定版、并快照同步到运行配置域的历史版本，支持版本追溯与回滚；并承载 1.7 节的配置覆盖登记。
>
> **域归属**：本章 **3 张表属研发固化域（`ddd`）**，由发布流程写入——发布是**研发侧**动作（产品交付物定版冻结）。
> 业务侧的两级覆盖（`APPLICATION`/`USER`）不在此列，改由 **`app_cfgoverride`**（见 8.19）承载。
>
> **本章归属说明**：3 张表在 §11 表清单中归为「产品层·发布」（`prod_*` 13 张之三），字段定义保留在本章以便集中阅读发布机制。

### 12.1 prod_release — 发布版本定义

> 一次发布产生一条版本记录，定义该版本的编号、状态、发布时间、内容范围与回滚目标。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `release_id` | integer | PK | 主键，序列 `seq_prod_release` |
| `row_uuid` | uuid | UN, NOT NULL | 全局行标识（UUID v4） |
| `release_no` | varchar(50) | UN, NOT NULL | 发布版本号（如 `REL-20260818-001`，对齐 `_no` → `varchar(50)` 后缀规范） |
| `release_name` | varchar(128) | NOT NULL | 发布名称（如"采购域 V2.0 发布"） |
| `prod_releasestatus_dict` | varchar(64) | NOT NULL, DEFAULT 'DRAFT' | 发布状态（字典）：`DRAFT`（草稿）/`RELEASED`（已发布）/`ROLLED_BACK`（已回滚）/`FAILED`（失败）。`_dict` 字典引用 |
| `prod_releasetype_dict` | varchar(64) | NOT NULL | 发布类型（字典）：`FULL`（全量）/`INCREMENT`（增量）。`_dict` 字典引用 |
| `prod_rollbacktype_dict` | varchar(64) | NOT NULL, DEFAULT 'SNAPSHOT' | 回滚类型（字典，v3.0 新增）：`SNAPSHOT`（快照回滚，按 `prod_release_detail` 整行快照反向执行）/`REVERSE`（补偿回滚，业务侧补偿处理，不依赖快照）。`_dict` 字典引用 |
| `released_by` | integer | NOT NULL | 发布人（app.user_id，`_by` 操作人后缀） |
| `release_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 发布时间 |
| `rollback_release_id` | integer | | → `prod_release.release_id`（回滚到的目标版本，回滚时记录） |
| `description_txt` | text | | 发布说明 |
| `create_by` | integer | NOT NULL | 创建人（app.user_id） |
| `create_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `update_by` | integer | NOT NULL | 最后修改人（app.user_id） |
| `update_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 最后修改时间 |
| `delete_flag` | smallint | NOT NULL, DEFAULT 0 | 逻辑删除标志 |
| `version_cnt` | integer | NOT NULL, DEFAULT 0 | 乐观锁版本号 |

> **设计要点**：发布是运行配置域配置更新的**唯一入口**。`release_no` 全局唯一；`rollback_release_id` 记录回滚目标版本；`prod_rollbacktype_dict` 声明回滚方式（默认快照型）——快照回滚按 `prod_release_detail` 的 `before_json`/`after_json` 反向执行，**只作用于运行配置域快照，不涉及业务数据域（`biz_*`）**（见 1.6 节）。

### 12.2 prod_release_detail — 发布明细

> 一次发布的**配置对象清单**：逐条记录本次发布纳入的配置对象（哪张表、哪条记录、变更类型），支撑精确追溯与定向回滚。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `release_detail_id` | integer | PK | 主键，序列 `seq_prod_release_detail` |
| `row_uuid` | uuid | UN, NOT NULL | 全局行标识（UUID v4） |
| `release_id` | integer | NOT NULL | → `prod_release.release_id`（所属发布版本，见 12.1） |
| `target_schema_name` | varchar(64) | NOT NULL | 目标 schema 名（如 `app`，字段名带 `_name` 后缀收尾） |
| `target_table_name` | varchar(128) | NOT NULL | 目标表名（如 `ui_page`、`cdm_entity_attribute`，字段名带 `_name` 后缀收尾） |
| `target_key_txt` | text | | 目标记录主键值文本（如 `page_id=123`，记录主键值文本，对齐 `_txt` → `text` 后缀规范） |
| `before_json` | jsonb | | **变更前整行快照（v3.0 新增）**：CREATE 行为空；UPDATE/DELETE 行为变更前完整行 json |
| `after_json` | jsonb | | **变更后整行快照（v3.0 新增）**：DELETE 行为空；CREATE/UPDATE 行为变更后完整行 json |
| `prod_changetype_dict` | varchar(64) | NOT NULL | 变更类型（字典）：`CREATE`（新增）/`UPDATE`（修改）/`DELETE`（删除）/`SYNC`（同步）。`_dict` 字典引用 |
| `create_by` | integer | NOT NULL | 创建人（app.user_id） |
| `create_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `update_by` | integer | NOT NULL | 最后修改人（app.user_id） |
| `update_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 最后修改时间 |
| `delete_flag` | smallint | NOT NULL, DEFAULT 0 | 逻辑删除标志 |
| `version_cnt` | integer | NOT NULL, DEFAULT 0 | 乐观锁版本号 |

> **设计要点**：
> - **对象定位**：`release_id + target_table_name + target_key_txt` 定位本次发布变更的具体配置对象（联合唯一约束名 `uk_prod_release_detail_target`）；`prod_changetype_dict` 表达变更类型
> - **回滚快照**：`before_json`/`after_json` 承载变更前后**整行快照**（v3.0，可回滚落地的载体）——回滚语义：UPDATE → 用 `before_json` 覆盖当前行；DELETE → 用 `after_json` 重建被删行；CREATE → 删除本行（业务数据域不在回滚范围，见 1.6 节）
> - **定位口径共用**：以三元组（`target_schema_name`/`target_table_name`/`target_key_txt`）定位变化对象，与 `prod_cfgoverride`（见 12.3）共用该三元组；`prod_cfgoverride` 另以 `json_path_txt` 定位覆盖点（见 12.3）
> - **配置策略纳入发布**：`prod_cfgpolicy`/`prod_cfgpolicyitem`（见 6.10/6.11）的增删改同样登记为本表明细行——策略是产品交付资产，随版本快照与回滚；但**客户侧的选择**（`app_system_product.cfgpolicy_code`）与**物化结果**（`app_menu.menu_param_json`）属运行侧事实，不进发布明细

### 12.3 prod_cfgoverride — 配置覆盖登记

> **配置覆盖（Config Override）**：**研发侧三级**配置覆盖（平台公共 / 产品级 / 业务场景级）的载体（v3.0 新增，见 1.7 节）。
> 任意研发侧层级的覆盖在本表登记，运行时按层级合并生成最终生效配置。
>
> **覆盖载体按域拆分**：本表（`ddd`）仅 `PLATFORM`/`PRODUCT`/`SCENARIO` 三级（研发侧固定层级，随产品固化发布）；
> 按客户产生的层级（`APPLICATION`/`USER`）属客户实例数据，与"研发固化域只读冻结"语义冲突，由 `app_cfgoverride`（`app`，见 8.19）承载。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `override_id` | integer | PK | 主键，序列 `seq_prod_cfgoverride` |
| `row_uuid` | uuid | UN, NOT NULL | 全局行标识（UUID v4） |
| `release_id` | integer | | → `prod_release.release_id`（固化进发布的版本，逻辑关联，见 12.1；空 = 未发布草稿） |
| `prod_overridelevel_dict` | varchar(64) | NOT NULL | 覆盖层级（字典）：`PLATFORM`（平台公共）/`PRODUCT`（产品级）/`SCENARIO`（业务场景级）。不含 `USER`（用户级在 `app_cfgoverride`，见 8.19），由 CHECK 限定取值域。`_dict` 字典引用 |
| `target_schema_name` | varchar(64) | NOT NULL | 被覆盖对象 schema（如 `ddd`） |
| `target_table_name` | varchar(128) | NOT NULL | 被覆盖对象表（如 `ui_page`、`ui_page_component`、`ui_datasource`） |
| `target_key_txt` | text | NOT NULL | 被覆盖对象主键值文本（如 `page_id=123`） |
| `json_path_txt` | text | NOT NULL | 覆盖点 JSON path（如 `layout_json.components[?(@.key=="list")].props`） |
| `override_json` | jsonb | NOT NULL | 覆盖值 |
| `cdm_status_dict` | varchar(64) | NOT NULL, DEFAULT 'DRAFT' | 状态（字典）：`DRAFT`（草稿）/`ACTIVE`（生效，参与合并）/`DEPRECATED`（废弃）。`_dict` 字典引用 |
| `create_by` | integer | NOT NULL | 创建人（app.user_id） |
| `create_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `update_by` | integer | NOT NULL | 最后修改人（app.user_id） |
| `update_ts` | timestamp | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 最后修改时间 |
| `delete_flag` | smallint | NOT NULL, DEFAULT 0 | 逻辑删除标志 |
| `version_cnt` | integer | NOT NULL, DEFAULT 0 | 乐观锁版本号 |

> **设计要点**：
> - **合并语义**：合并输入 = 基线配置（发布快照）+ 本表与 `app_cfgoverride`（见 8.19）中 `cdm_status_dict='ACTIVE'` 的覆盖行，
>   按层级排序（PLATFORM → PRODUCT → SCENARIO → APPLICATION → USER），高层级覆盖低层级，按 `json_path_txt` 定位到字段属性级（见 1.7 节）；
> - **两表 UNION 口径**：消费侧对两表按**显式列清单**（层级、定位三元组、`json_path_txt`、`override_json`、`cdm_status_dict`）做 `UNION ALL`——
>   本表多 `release_id`、少 `app_system_id`，`app_cfgoverride` 反之；**公共列结构必须保持一致**，否则 UNION 不成立；
> - **联合唯一**：约束名 `uk_prod_cfgoverride_target_path` = `(prod_overridelevel_dict, target_table_name, target_key_txt, json_path_txt)`——同层级同覆盖点只允许一条生效记录；
> - **生效粒度**：覆盖行独立版本——新建/修改后置 `ACTIVE` 即时参与合并（在线读库方式）；随代码部署的导出 JSON 由发布流程按当前 `ACTIVE` 覆盖行**固化**生成（导出的是合并产物，覆盖源留库，见 1.7 消费方式）；
> - **纳入发布**：覆盖行参与发布时写入 `release_id`，并随 `prod_release_detail` 快照记录变更（见 1.6 节），保证覆盖可审计、可回滚；
> - **对象定位口径**：`target_schema_name`/`target_table_name`/`target_key_txt` 与 `prod_release_detail`（见 12.2）共用。
