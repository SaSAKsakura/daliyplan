## 9. 属性配置模型（业务配置）

> 属性上的**业务配置**描述**字段的值如何约束、如何编辑**——字典引用、精度、可编辑性、校验规则、顺序。属领域侧业务语义，非查询型配置，存于 `cdm_entity_attribute.config_json` / `cdm_valueobject_attribute.config_json`。

### 9.1 设计目标与定位

| 目标 | 说明 |
|------|------|
| **配置与语义分离** | 语义性字段（`required_flag`/`unique_flag`/`pk_flag`、数据类型、引用关系）仍用独立列表达；`config_json` 仅承载业务配置 |
| **全部 JSON 驱动** | 业务配置以 jsonb 承载，与前端 `DataFieldSchema` 对齐，可视化配置工具（属性面板）可直接读写 |
| **查询与约束分离** | 查询与约束语义由独立列承载；**字段级取值/取值范围约束由本表 `validationRules`（9.3）执行**，枚举由数据字典定义，跨字段/跨步骤的业务规则在场景层活动描述（见 2.5）并由业务服务实现 |

### 9.2 业务配置 JSON 结构（`config_json`）

> 保留在 `cdm_entity_attribute.config_json` / `cdm_valueobject_attribute.config_json` 的**业务侧配置**。`*_flag` 在模型列中已有等价语义列的字段（如 `required`↔`required_flag`）不重复；**字段级取值约束由本表 `validationRules`（见 9.3）承载**，是本模型唯一的字段级校验执行载体；跨字段/跨步骤的业务规则不在本处定义——其自然语言描述在场景层活动（`prod_activity.rule_txt`，见 2.5），可执行部分经 `custom.validatorId` 指向后端校验器实现。

| JSON 键 | 类型 | 说明 |
|---------|------|------|
| `dictCode` | string | 引用统一数据字典类型编码（如 `ORDER_STATUS`），决定字段合法值集合（优先于 `enumMap`） |
| `enumMap` | object | 枚举值映射 `{ value: label }`，定义合法枚举值集合 |
| `options` | array | 静态选项 `[{ label, value, disabled }]`，定义可选值集合 |
| `precision` | integer | 小数精度（业务数据精度） |
| `editableOnCreate` | boolean | 创建模式是否可编辑（缺省 true） |
| `editableOnUpdate` | boolean | 更新模式是否可编辑（缺省 true） |
| `validationRules` | array | 校验规则列表（见 9.3），约束字段合法值 |
| `order` | integer | 属性展示顺序（与 `cdm_entity_attribute.sort_order` 保持一致） |

> **业务配置示例（订单「状态」属性）：**

```json
{
  "dictCode": "ORDER_STATUS",
  "editableOnCreate": true,
  "editableOnUpdate": false,
  "validationRules": [
    { "type": "required", "message": "请选择订单状态" }
  ]
}
```

### 9.3 校验规则（`validationRules`，业务配置）

> 对应前端 `ValidationRule[]` 与 `YiUtils.validate` 校验函数。`required` 与模型列 `required_flag` 保持一致，其余校验在配置 JSON 中声明。

| 规则 `type` | 附加字段 | 说明 |
|------------|---------|------|
| `required` | `message` | 必填（`null`/`undefined`/`''`/`[]` 视为未填写） |
| `pattern` | `pattern`(正则), `message` | 正则匹配 |
| `range` | `min`, `max`, `message` | 数值/字符串长度范围 |
| `length` | `min`, `max`, `message` | 字符串长度 |
| `email` | `message` | 邮箱格式 |
| `phone` | `message` | 手机号格式 |
| `idCard` | `message` | 身份证号 |
| `url` | `message` | URL 格式 |
| `decimal` | `precision`, `message` | 合法小数 |
| `enum` | `dictCode`/`enumMap`, `message` | 值必须在枚举/字典内 |
| `custom` | `validatorId` | 引用校验器，支持同步/异步校验 |
| `crossField` | `expression`, `message` | 跨字段校验表达式 |

**校验时序**：失焦（blur）自动校验 → 值变化（change）校验 → 保存前（`beforeSave`）数据源级全量校验 → 汇总定位。

> **数据完整性说明**：业务配置（`config_json`）属**非查询型配置**，不参与业务查询过滤；查询与约束语义由独立列（`required_flag`/`unique_flag`/`pk_flag`）承载，**字段级取值/取值范围约束由本节 `validationRules` 承载并执行**（规则类型见上表），枚举值由数据字典（`dictCode`/`app_dict`，`cdm_dict` 发布同步）定义；跨字段/跨步骤的业务规则不在本表定义——其自然语言描述在场景层活动（`prod_activity.rule_txt`，见 2.5），本表只承载单字段可表达的约束。涉及敏感字段的存储须配合 `app_enc` 统一处理，配置本身不存敏感值。
>
> **与场景层规则描述的边界**：**本表是执行载体，场景层活动是描述载体**——`validationRules` 负责"跑"（引擎直接读取执行），`prod_activity.rule_txt`（见 2.5）负责"记"（该业务步骤上有什么规矩，自然语言）。**模型层不设规则表**；`crossField`/`custom` 类校验虽落在本表执行，其规则语义仍应在场景层活动中描述，二者一执行一描述，不构成重复建模。
